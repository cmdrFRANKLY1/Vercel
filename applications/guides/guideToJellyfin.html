Jellyfin Setup & Referenz Jellyfin Setup & Reference

Jellyfin ist ein freier, quelloffener Medienserver zum Streamen von Filmen, Serien, Musik, Hörbüchern und Live-TV. Er ist ein Fork von Emby und vollständig werbefrei sowie ohne kostenpflichtige Premium-Funktionen. Dieser Guide behandelt Installation, Ersteinrichtung, Medienbibliotheken, Hardware-Transkodierung, Benutzerverwaltung, Fernzugriff und Wartung. Jellyfin is a free, open-source media server for streaming movies, TV shows, music, audiobooks, and live TV. It is a fork of Emby and is completely ad-free with no paid premium features. This guide covers installation, initial setup, media libraries, hardware transcoding, user management, remote access, and maintenance.

1. Einführung & Installation 1. Intro & Installation

Jellyfin läuft auf nahezu jeder Linux-Distribution, in Docker oder als native Paketinstallation. Für die Wiedergabe empfiehlt sich zusätzlich ffmpeg (bei den meisten Paketen bereits als Abhängigkeit enthalten). Jellyfin runs on almost any Linux distribution, in Docker, or as a native package installation. For playback, ffmpeg is also recommended (already included as a dependency in most packages).

Installation (Debian/Ubuntu) Installation (Debian/Ubuntu)

curl -fsSL https://repo.jellyfin.org/install-debuntu.sh | sudo bash sudo systemctl enable --now jellyfin

Das offizielle Skript richtet das Repository ein, installiert Jellyfin und startet den Dienst. The official script sets up the repository, installs Jellyfin, and starts the service.

Installation (Arch Linux) Installation (Arch Linux)

sudo pacman -S jellyfin jellyfin-server jellyfin-web sudo systemctl enable --now jellyfin

Unter Arch wird zwischen Server, Web-Oberfläche und optionalem jellyfin-media-player unterschieden. On Arch, a distinction is made between the server, the web interface, and the optional jellyfin-media-player.

Installation via Docker Compose Installation via Docker Compose

Für Container-Umgebungen empfiehlt sich die offizielle jellyfin/jellyfin-Image. Achten Sie darauf, dass user: auf die UID/GID des Besitzers Ihrer Mediendateien gesetzt ist. For container environments, the official jellyfin/jellyfin image is recommended. Make sure user: is set to the UID/GID that owns your media files.

services: jellyfin: image: jellyfin/jellyfin:latest container_name: jellyfin user: 1000:1000 ports: - "8096:8096" - "7359:7359/udp" volumes: - /srv/jellyfin/config:/config - /srv/jellyfin/cache:/cache - /srv/media:/media:ro restart: unless-stopped

Starten mit docker compose up -d. Für Hardware-Transkodierung muss zusätzlich /dev/dri durchgereicht werden. Start with docker compose up -d. For hardware transcoding, /dev/dri must also be passed through.

Dienste überprüfen Checking Services

Der Jellyfin-Dienst läuft als systemd-Unit jellyfin.service. Logs lassen sich bequem über journalctl verfolgen. The Jellyfin service runs as the systemd unit jellyfin.service. Logs can be followed conveniently via journalctl.

3. Bibliotheken & Transkodierung 3. Libraries & Transcoding

Medienbibliotheken anlegenCreating Media Libraries

Jellyfin erwartet eine saubere Ordnerstruktur, damit Metadaten (Titel, Cover, Beschreibung) automatisch korrekt zugeordnet werden. Empfohlen ist folgendes Schema: Jellyfin expects a clean folder structure so that metadata (titles, artwork, descriptions) is matched correctly and automatically. The following layout is recommended:

1. Verzeichnisse erstellen:1. Create directories:

sudo mkdir -p /srv/media/{Filme,Serien,Musik} sudo chown -R jellyfin:jellyfin /srv/media sudo chmod -R 0755 /srv/media

2. Empfohlene Ordnerstruktur:2. Recommended folder structure:

/srv/media/Filme/Inception (2010)/Inception (2010).mkv /srv/media/Serien/Breaking Bad/Season 01/Breaking Bad S01E01.mkv /srv/media/Musik/Artist/Album/01 - Track.flac

Im Webinterface unter Dashboard → Bibliotheken → Bibliothek hinzufügen wählen Sie den passenden Inhaltstyp (Filme, Serien, Musik …) und den jeweiligen Pfad. In the web UI, go to Dashboard → Libraries → Add Media Library, choose the appropriate content type (Movies, Shows, Music, …) and the corresponding path.

Hardware-TranskodierungHardware Transcoding

Transkodierung ist nötig, wenn ein Client ein Format nicht direkt abspielen kann. Ohne Hardware-Beschleunigung lastet dies die CPU stark aus. Intel- und AMD-GPUs nutzen VAAPI, NVIDIA nutzt NVENC/NVDEC. Transcoding is required when a client cannot play a format directly. Without hardware acceleration, this puts a heavy load on the CPU. Intel and AMD GPUs use VAAPI, NVIDIA uses NVENC/NVDEC.

1. Benutzer zur Videogruppe hinzufügen:1. Add user to the video group:

sudo usermod -aG video,render jellyfin sudo systemctl restart jellyfin

2. Verfügbare Renderknoten prüfen:2. Check available render nodes:

ls -l /dev/dri/ vainfo

3. In Jellyfin aktivieren:3. Enable in Jellyfin:

Dashboard → Wiedergabe → Transkodierung → Hardware-Beschleunigung: VAAPI / QSV / NVENC → Gerät: /dev/dri/renderD128

Aktivieren Sie zusätzlich alle Formate, die Ihre GPU unterstützt (H.264, HEVC, VP9, AV1) und lassen Sie das Häkchen bei „Transkodierung erlauben“ gesetzt. Additionally, enable all formats your GPU supports (H.264, HEVC, VP9, AV1) and keep the "Allow transcoding" checkbox ticked.

4. Benutzer & Rechte 4. Users & Permissions

Jellyfin unterscheidet zwischen dem Linux-Benutzer jellyfin (unter dem der Dienst läuft) und den Jellyfin-Benutzern im Webinterface. Der Dienstbenutzer benötigt Leserechte auf alle Medienordner. Jellyfin distinguishes between the Linux user jellyfin (which the service runs as) and the Jellyfin users in the web UI. The service user needs read access to all media folders.

Rechte für Medienordner setzen:Set permissions for media folders:

# Besitzer des Medienordners setzen sudo chown -R jellyfin:jellyfin /srv/media # Leserechte für alle, Schreibrechte für Besitzer sudo chmod -R 0755 /srv/media # Optional: eigene Gruppe für gemeinsamen Zugriff sudo groupadd -f media sudo usermod -aG media jellyfin sudo chown -R :media /srv/media sudo chmod -R 0775 /srv/media

Benutzer im Webinterface anlegen:Create users in the web UI:

Dashboard → Benutzer → Benutzer hinzufügen → Name, Passwort, Bibliothekszugriff festlegen

Pro Benutzer lassen sich einzelne Bibliotheken freigeben oder sperren, ebenso die Erlaubnis zum Transkodieren, Löschen von Medien und zur Fernsteuerung anderer Geräte. Per user, individual libraries can be granted or blocked, as well as permission to transcode, delete media, and remotely control other devices.

Dienste neu startenRestart Services

Nach Änderungen an Benutzergruppen oder systemd-Konfiguration muss der Dienst neu gestartet werden. After changing user groups or the systemd configuration, the service must be restarted.

sudo systemctl restart jellyfin

Rechte prüfenVerify permissions

sudo -u jellyfin ls -la /srv/media

5. Fernzugriff & Sicherheit 5. Remote Access & Security

Reverse Proxy

Ein Nginx-Reverse-Proxy mit TLS-Zertifikat (Let's Encrypt) ist der sauberste Weg, Jellyfin von außen erreichbar zu machen. Der Dienst selbst bleibt dabei nur auf 127.0.0.1:8096 lauschen. An Nginx reverse proxy with a TLS certificate (Let's Encrypt) is the cleanest way to make Jellyfin reachable from outside. The service itself keeps listening only on 127.0.0.1:8096.

server { listen 443 ssl http2; server_name jellyfin.example.com; ssl_certificate /etc/letsencrypt/live/jellyfin.example.com/fullchain.pem; ssl_certificate_key /etc/letsencrypt/live/jellyfin.example.com/privkey.pem; location / { proxy_pass http://127.0.0.1:8096; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; proxy_buffering off; } }

VPN (Tailscale/WireGuard)

Wenn kein Port nach außen geöffnet werden soll, ist ein Mesh-VPN wie Tailscale die einfachste Lösung. Der Server erhält eine private IP und ist nur für eingeladene Geräte erreichbar. If you don't want to open any port to the outside, a mesh VPN like Tailscale is the simplest solution. The server gets a private IP and is only reachable by invited devices.

curl -fsSL https://tailscale.com/install.sh | sh sudo tailscale up # Erreichbar unter: http://jellyfin-server:8096

HTTPS in Jellyfin konfigurieren Configuring HTTPS in Jellyfin

Alternativ zum Reverse Proxy kann Jellyfin auch selbst TLS beherrschen. Hinterlegen Sie das Zertifikat im Dashboard und aktivieren Sie „Sichere Verbindungen erzwingen“. As an alternative to a reverse proxy, Jellyfin can handle TLS itself. Add the certificate in the dashboard and enable "Require secure connections".

Dashboard → Netzwerk → HTTPS aktivieren → Zertifikatspfad: /etc/letsencrypt/live/jellyfin.example.com/ → Öffentlicher HTTPS-Port: 8920 → Sichere Verbindungen erzwingen: AN

Öffnen Sie niemals Port 8096 ungeschützt ins Internet — die Anmeldung würde im Klartext übertragen! Never expose port 8096 to the internet without protection — credentials would be transmitted in plain text!

Backup & Wiederherstellung Backup & Restore

Sichern Sie Konfiguration und Datenbank regelmäßig. Die Medien selbst müssen nicht Teil des Backups sein, sofern sie anderweitig gesichert werden. Back up the configuration and database regularly. The media itself does not need to be part of the backup if it is backed up elsewhere.

# Dienst stoppen, damit die Datenbank konsistent ist sudo systemctl stop jellyfin # Backup erstellen sudo tar -czf jellyfin-backup-$(date +%F).tar.gz \ /etc/jellyfin /var/lib/jellyfin sudo systemctl start jellyfin

Backup automatisieren (Cron):Automate backup (cron):

sudo crontab -e # Jeden Sonntag um 03:30 Uhr sichern 30 3 * * 0 tar -czf /srv/backup/jellyfin-$(date +\%F).tar.gz /etc/jellyfin /var/lib/jellyfin

Wiederherstellung: Dienst stoppen, Archiv mit sudo tar -xzf … entpacken, Dienst starten. Prüfen Sie anschließend die Rechte der entpackten Dateien (chown -R jellyfin:jellyfin). Restore: stop the service, extract the archive with sudo tar -xzf …, start the service. Afterwards, check the permissions of the extracted files (chown -R jellyfin:jellyfin).
