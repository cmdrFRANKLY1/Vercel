Tailscale Setup & Referenz Tailscale Setup & Reference

Tailscale ist ein Zero-Config-VPN, das auf WireGuard® basiert. Es erstellt ein verschlüsseltes Mesh-Netzwerk (ein Tailnet) zwischen Ihren Geräten, sodass diese direkt miteinander kommunizieren können, selbst durch Firewalls oder NAT hinweg. Dieser Guide behandelt Architektur, plattformübergreifende Installation und fortgeschrittene Routing-Features. Tailscale is a zero-config VPN built on top of WireGuard®. It creates an encrypted mesh network (a tailnet) between your devices, allowing them to communicate directly, even through firewalls or NAT. This guide covers architecture, cross-platform installation, and advanced routing features.

1. Architektur & Grundlagen 1. Architecture & Basics

Im Gegensatz zu traditionellen Hub-and-Spoke-VPNs baut Tailscale ein Peer-to-Peer-Mesh-Netzwerk auf. Der Traffic fließt direkt zwischen den Knoten (Nodes), was die Latenz reduziert und zentrale Flaschenhälse eliminiert. Unlike traditional hub-and-spoke VPNs, Tailscale builds a peer-to-peer mesh network. Traffic flows directly between nodes, reducing latency and eliminating centralized bottlenecks.

Das Tailnet (100.x.y.z) The Tailnet (100.x.y.z)

Jedes authentifizierte Gerät erhält eine statische IP-Adresse aus dem Carrier-Grade NAT (CGNAT) Bereich 100.64.0.0/10. Diese IP bleibt konstant, unabhängig vom physischen Standort des Geräts. Every authenticated device receives a static IP address from the Carrier-Grade NAT (CGNAT) range 100.64.0.0/10. This IP remains constant regardless of the device's physical location.

Control Plane vs. Data Plane Control Plane vs. Data Plane

Tailscale verwaltet nur die Control Plane (Schlüsselaustausch über SSO). Die eigentlichen Daten (Data Plane) fließen verschlüsselt direkt zwischen den Endgeräten. Tailscale kann den Traffic nicht entschlüsseln. Tailscale only manages the Control Plane (key exchange via SSO). The actual data (Data Plane) flows encrypted directly between end devices. Tailscale cannot decrypt the traffic.

3. Core Features & Routing 3. Core Features & Routing

MagicDNS

Tailscale betreibt einen lokalen DNS-Server (100.100.100.100) auf jedem Knoten. Mit MagicDNS können Sie Geräte über ihren Hostnamen ansprechen, ohne sich IPs merken zu müssen. Tailscale runs a local DNS server (100.100.100.100) on every node. MagicDNS allows you to address devices by their hostname without remembering IPs.

ping my-server ssh user@my-server

Exit Nodes

Standardmäßig routet Tailscale nur internen Traffic. Durch die Deklaration eines "Exit Nodes" leiten Sie Ihren gesamten Internetverkehr (0.0.0.0/0) durch diesen Knoten (ähnlich einem klassischen VPN). By default, Tailscale only routes internal traffic. By declaring an "Exit Node," you route your entire internet traffic (0.0.0.0/0) through this node (similar to a classic VPN).

1. Knoten als Exit Node anbieten (Server):1. Advertise node as Exit Node (Server):

sudo tailscale up --advertise-exit-node

2. Im Admin Console genehmigen:2. Approve in Admin Console:

Im Tailscale Dashboard unter "Machines" → "Edit route settings" → "Use as exit node" aktivieren. In the Tailscale Dashboard under "Machines" → "Edit route settings" → check "Use as exit node".

3. Exit Node nutzen (Client):3. Use Exit Node (Client):

sudo tailscale up --exit-node=<ip-oder-name> --exit-node-allow-lan-access

Subnet Routing

Macht physische LAN-Netzwerke für das Tailnet zugänglich. Ideal für Drucker, IoT-Geräte oder Server, auf denen der Tailscale-Client nicht installiert werden kann. Makes physical LAN networks accessible to the tailnet. Ideal for printers, IoT devices, or servers where the Tailscale client cannot be installed.

1. IP Forwarding auf dem Linux-Router aktivieren:1. Enable IP Forwarding on the Linux router:

echo 'net.ipv4.ip_forward = 1' | sudo tee -a /etc/sysctl.d/99-tailscale.conf sudo sysctl -p /etc/sysctl.d/99-tailscale.conf

2. Subnetzwerk bewerben:2. Advertise Subnet:

sudo tailscale up --advertise-routes=192.168.0.0/24,10.0.0.0/8

3. Routen auf Clients akzeptieren:3. Accept routes on clients:

(Windows/macOS akzeptieren Routen meist standardmäßig). Linux: (Windows/macOS typically accept routes by default). Linux:

sudo tailscale up --accept-routes
