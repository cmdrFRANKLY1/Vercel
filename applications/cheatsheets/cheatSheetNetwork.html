Netzwerk-ReferenzNetwork Cheatsheet

Ein Netzwerkprotokoll ist ein exaktes Regelwerk, das bestimmt, wie Computer innerhalb eines Netzwerks miteinander kommunizieren. Diese Referenz dient als umfassendes Kompendium für angehende Fachinformatiker (FISI) und Systemadministratoren und umfasst die Themenbereiche OSI-Modell, Adressierung (IPv4/IPv6), Transport (TCP/UDP), Anwendungsprotokolle (Samba, SSH, etc.), Diagnose-Werkzeuge sowie Sicherheitskonzepte.

A Network Protocol is an exact set of rules that determines how computers communicate with each other within a network. This reference serves as a comprehensive compendium for IT professionals and system administrators, covering the OSI model, addressing (IPv4/IPv6), transport protocols (TCP/UDP), application protocols (Samba, SSH, etc.), diagnostic tools, and security concepts.

1. Transportschicht (TCP & UDP) 1. Transport Layer (TCP & UDP)

Auf der Transportschicht des OSI-Modells (Schicht 4) entscheiden zwei primäre Protokolle über die Art der Datenübertragung: das zuverlässige Transmission Control Protocol (TCP) und das verbindungslose User Datagram Protocol (UDP).

At the Transport Layer of the OSI model (Layer 4), two primary protocols determine how data is transmitted: the reliable Transmission Control Protocol (TCP) and the connectionless User Datagram Protocol (UDP).

ZuverlässigkeitReliability Garantiert. Verlorene Pakete werden neu angefordert.Guaranteed. Lost packets are retransmitted. Keine Garantie. Verluste werden ignoriert.No guarantee. Packet loss is ignored.
ReihenfolgeOrdering Geordnet (durch Sequence Numbers)Ordered (via Sequence Numbers) Ungeordnet (Anwendung muss sortieren)Unordered (application must handle)

Um die garantierte Zustellung zu gewährleisten, baut TCP vor der eigentlichen Datenübertragung eine logische Verbindung auf:

To guarantee delivery, TCP establishes a logical connection before any actual data transmission:

  1. SYN: Der Client initiiert die Verbindung und sendet eine zufällige Sequenznummer (z.B. Seq=100) an den Server.The client initiates the connection and sends a random sequence number (e.g., Seq=100) to the server.
  2. SYN-ACK: Der Server bestätigt den Erhalt (Ack=101) und sendet seine eigene Start-Sequenznummer (z.B. Seq=300).The server acknowledges receipt (Ack=101) and sends its own starting sequence number (e.g., Seq=300).
  3. ACK: Der Client bestätigt die Sequenznummer des Servers (Ack=301). Die Verbindung ist nun ESTABLISHED.The client acknowledges the server's sequence number (Ack=301). The connection is now ESTABLISHED.

Der Verbindungsabbau (Teardown) erfolgt über vier Schritte: Client sendet FIN → Server bestätigt mit ACK → Server sendet eigenes FIN → Client bestätigt mit ACK.

Connection termination (Teardown) requires four steps: Client sends FIN → Server acknowledges with ACK → Server sends its own FIN → Client acknowledges with ACK.

3. IPv4 & Subnetting 3. IPv4 & Subnetting

IPv4-Adressen sind 32 Bit lang (4 Oktette, z.B. 192.168.1.100). Da der Adressraum erschöpft ist, werden Netze durch Subnetting in kleinere Segmente unterteilt.

IPv4 addresses are 32 bits long (4 octets, e.g., 192.168.1.100). Because the address space is exhausted, networks are divided into smaller segments using Subnetting.

Das klassische Classful Routing wurde durch CIDR abgelöst, ist aber weiterhin prüfungsrelevant. Private IP-Bereiche (RFC 1918) werden im Internet nicht geroutet und benötigen NAT.

Classic Classful Routing has been replaced by CIDR, but remains relevant for exams. Private IP ranges (RFC 1918) are not routed on the public internet and require NAT.

3.2 Subnetting: Magic Number Methode 3.2 Subnetting: Magic Number Method

Beispiel:Example: 192.168.10.100 /26 (Mask: 255.255.255.192).

  1. Interessantes Oktett: Das erste Oktett der Maske, das nicht 255 oder 0 ist (hier: 192).
  2. Magic Number (Blockgröße): 256 - 192 = 64. Das Netz springt in 64er-Blöcken.
  3. Netzwerkadresse: Welches Vielfache von 64 passt in die IP 100? Es ist die 64. → 192.168.10.64.
  4. Broadcast-Adresse: Nächster Block (64+64=128) minus 1 → 192.168.10.127.
  5. Nutzbare Hosts: Von .65 bis .126 (Anzahl: 2^(32-26) - 2 = 62 Hosts).
  1. Interesting Octet: The first octet of the mask that is not 255 or 0 (here: 192).
  2. Magic Number (Block size): 256 - 192 = 64. Subnets increment in blocks of 64.
  3. Network Address: Which multiple of 64 fits into the IP 100? It's 64. → 192.168.10.64.
  4. Broadcast Address: Next block (64+64=128) minus 1 → 192.168.10.127.
  5. Usable Hosts: From .65 to .126 (Total: 2^(32-26) - 2 = 62 Hosts).

4. IPv6 4. IPv6

IPv6 verwendet 128 Bit lange Adressen (8 Blöcke in Hexadezimal). Es gibt keinen Broadcast mehr (ersetzt durch Multicast) und NAT ist obsolet.

IPv6 uses 128-bit addresses (8 hexadecimal blocks). Broadcasts are removed (replaced by Multicast) and NAT is obsolete.

4.1 Verkürzungsregeln 4.1 Abbreviation Rules

  • Führende Nullen: Dürfen innerhalb eines Hextets entfallen (0db8 → db8).
  • Nullenkompression: Ein einziger Block aus reinen Null-Hextets darf durch :: ersetzt werden. Darf strikt nur einmal geschehen!
  • Leading Zeros: Can be omitted within a block (0db8 → db8).
  • Zero Compression: A single contiguous block of all-zero blocks can be replaced by ::. This can strictly only happen once per address!

6. Netzwerksicherheit 6. Network Security

6.1 CIA Triade 6.1 CIA Triad

Confidentiality

Nur autorisierte Personen dürfen Daten lesen. Realisiert durch Verschlüsselung.

Only authorized entities can read data. Realized via Encryption.

Integrity

Daten dürfen nicht unbemerkt verändert werden. Realisiert durch Hash-Werte (SHA-256).

Data cannot be altered unnoticed. Realized via Hash values (SHA-256).

Availability

Systeme müssen erreichbar sein. Geschützt durch Redundanz (RAID, Cluster).

Systems must be accessible. Protected via redundancy (RAID, Clusters).
