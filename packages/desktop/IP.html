TCP & UDP für Strolchfreunde

Der TCP 3-Way Handshake

Bevor Daten zuverlässig gesendet werden können, müssen sich Client und Server "absprechen". Bewege die Maus über die gestrichelten Wörter und farbigen Zahlen, um exakt zu sehen, wie Sequence- und Acknowledgment-Nummern wandern.

1

Client sendet SYN (Synchronize)

Der Client möchte eine Verbindung aufbauen. Er erzeugt eine zufällige Startnummer (Sequence Number).

Paket-Details (Client → Server): Flag: SYN
Der Client sagt: "Lass uns reden! Meine Startnummer ist Seq=100".
Diese Nummer merkt sich der Server für den nächsten Schritt.
2

Server sendet SYN-ACK

Der Server bestätigt den Erhalt (ACK) und sendet seinerseits eine Anfrage zur Synchronisierung (SYN).

Paket-Details (Server → Client): Flags: SYN + ACK
Der Server sagt: "Ich habe deine Anfrage erhalten! Als Bestätigung sende ich dir deine Nummer + 1 zurück: Ack=101.
Außerdem hier meine eigene zufällige Startnummer: Seq=300".
3

Client sendet ACK (Acknowledgment)

Der Client schließt den Handshake ab, indem er die Nummer des Servers bestätigt.

Paket-Details (Client → Server): Flag: ACK
Der Client antwortet: "Alles klar! Meine eigene Sequenznummer rückt nun auf Seq=101 vor.
Und ich bestätige deine Startnummer mit Nummer + 1: Ack=301."

Der Verbindungsabbau (Teardown)

TCP baut Verbindungen geordnet auf und ab. Meist passiert dies in 4 Schritten (FIN, ACK, FIN, ACK).

Schritt 1
FIN

Client sendet FIN: "Ich bin fertig mit Senden."

Schritt 2
ACK

Server bestätigt FIN mit ACK. "Verstanden." (Server kann aber noch Daten senden).

Schritt 3
FIN

Server sendet FIN: "Ich bin nun auch fertig."

Schritt 4
ACK

Client bestätigt FIN mit ACK. Verbindung wird komplett geschlossen.

Die Giganten: TCP vs UDP

Beide Protokolle arbeiten auf Schicht 4 (Transportschicht) des OSI-Modells. Während TCP (Transmission Control Protocol) wie ein Einschreiben mit Rückschein funktioniert (sicher, geordnet, aber langsamer), ist UDP (User Datagram Protocol) wie eine Postkarte (schnell, aber keine Garantie, dass sie ankommt).

TCP

Zuverlässig
  • Verbindungsorientiert: Nutzt den 3-Way-Handshake vor dem Datenaustausch.
  • Garantierte Zustellung: Verlorene Pakete werden automatisch neu angefordert (Retransmission).
  • Geordnet: Pakete werden anhand der Sequence-Number beim Empfänger in der exakt richtigen Reihenfolge zusammengesetzt.
  • Overhead: Schwerer (Header ist min. 20 Bytes) und langsamer durch Bestätigungen (ACKs).

Typische Anwendungen (Ports):

HTTP (80) HTTPS (443) SSH (22) FTP (21)

UDP

Verbindungslos
  • Feuer und Vergessen: Kein Handshake. Daten werden sofort in Richtung Empfänger gefeuert.
  • Keine Garantie: Keine Bestätigung. Verlorene Pakete sind weg.
  • Ungeordnet: Pakete können in beliebiger Reihenfolge ankommen (Applikation muss das handhaben).
  • Leichtgewicht: Sehr schneller und winziger Header (nur 8 Bytes). Kaum Latenz.

Typische Anwendungen (Ports):

DNS (53) DHCP (67/68) VoIP / SIP (5060) Videospiele
