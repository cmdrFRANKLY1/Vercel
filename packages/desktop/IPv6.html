IPv6 für Strolchfreunde

Der rote Faden: Die Hex-Hextet-Methode

IPv6 ist kein anderes Universum – nur ein anderes Zahlensystem. Bewege die Maus über die gestrichelten Wörter und farbigen Werte, um exakt zu sehen, wie die Zahlen von Schritt zu Schritt wandern. Begleiten wir das Beispiel 2001:db8:abcd:1234::1 /56.

1

Interessantes Hextet finden

IPv6 hat 128 Bit, aufgeteilt in 8 Blöcke (Hextets) à 16 Bit. Die Präfixlänge verrät dir, wie viele Bits zum Netz gehören – der Rest des Hextets, in dem die Grenze landet, ist unser interessantes Hextet.

Unser Beispiel: /56 heißt 56 Netz-Bits. Das sind 3 volle Hextets (3 × 16 = 48 Bit) plus 8 Bit aus dem 4. Hextet.
Damit ist das 4. Hextet unser interessantes Hextet – dort steht der Wert 0x1234.
2

Schrittweite berechnen

Ein Hextet hat 16 Bit. Nimm die Host-Bits aus Schritt 1 und rechne 2^(16 − Host-Bits). Das Ergebnis ist die Blockgröße – unsere IPv6-Magic-Number in Hex.

Unser Beispiel: 2^(16 − 8) = 2^8 = 256 = 0x100.
Unsere Subnetze springen im 4. Hextet also in 0x100er-Schritten (0x1100, 0x1200, 0x1300, …).
3

Netzwerkadresse finden

Nutze die Schrittweite aus Schritt 2 und schau dir den Hextet-Wert deiner IP an. Runde ihn auf das nächstkleinere Vielfache der Schrittweite ab.

Unser Beispiel: Die IP ist 2001:db8:abcd:1234::1.
Welches Vielfache von 0x100 ist kleiner oder gleich 0x1234? Das ist 0x1200.
Das Netz, das wir für den nächsten Schritt festhalten, ist also 2001:db8:abcd:1200::/56.
4

Ende des Blocks bestimmen

Addiere die Schrittweite auf das Netz – das ist der Start des nächsten Subnetzes. Eins davor ist das letzte Hextet unseres Blocks. Der Rest wird mit ffff aufgefüllt.

Unser Beispiel: Unser Block startet bei 0x1200.
Das nächste Netz startet bei 0x1200 + 0x100 = 0x1300.
Eins davor: 0x1300 − 1 = 0x12ff.
Die letzte Adresse lautet 2001:db8:abcd:12ff:ffff:ffff:ffff:ffff.
5

Bereich & Besonderheiten

Damit hast du den kompletten Bereich. Aber Achtung: IPv6 kennt keine Broadcast-Adresse – Multicast übernimmt diese Aufgabe.

Unser Beispiel: Netzwerk: 2001:db8:abcd:1200:: (als Subnet-Router-Anycast reserviert)
Erste nutzbare IP: Netz + 1 → 2001:db8:abcd:1200:: + 1 = 2001:db8:abcd:1200::1
Letzte IP: 2001:db8:abcd:12ff:ffff:ffff:ffff:ffff (voll nutzbar – kein Broadcast!)

Die zwei Verkürzungsregeln

128 Bit sind lang. Deshalb darf man IPv6-Adressen abkürzen – aber nur nach festen Regeln.

1

Führende Nullen im Hextet weglassen

Innerhalb eines Hextets dürfen führende Nullen gestrichen werden – abschließende Nullen nicht!

2001:0db8:0000:0000:0000:0000:0000:0001
↓
2001:db8:0:0:0:0:0:1
2

Einmal :: für den längsten Nullblock

Ein einziger, zusammenhängender Block aus Null-Hextets darf durch :: ersetzt werden. Der längste Block gewinnt.

2001:db8:0:0:0:0:0:1
↓
2001:db8::1

Die goldene Regel: :: darf nur einmal pro Adresse vorkommen. Sonst wäre die Adresse nicht mehr eindeutig rekonstruierbar.

Bei Gleichstand (zwei gleich lange Nullblöcke) wird der erste ersetzt. Beispiel: 2001:0:0:1:0:0:0:1 → 2001::1:0:0:0:1

Adresstypen statt Klassen

IPv6 kennt keine starren Klassen mehr. Stattdessen gibt es Adresstypen, die an festen Präfixen erkennbar sind. Das erste Byte (genauer: die ersten Bits) verrät, wofür eine Adresse gedacht ist. Ein Interface hat dabei fast immer mehrere Adressen gleichzeitig – mindestens eine Link-Local und eine Globale.

Global Unicast

2000::/3
  • Bereich: 2000:: – 3fff:…
  • Routbar: Ja (im Internet)
  • Entspricht: öffentlicher IPv4
  • Das Gegenstück zur "öffentlichen" IPv4-Adresse. Wird vom Provider zugewiesen.

Link-Local

fe80::/10
  • Bereich: fe80::/10
  • Routbar: Nein (nur lokal)
  • Vergabe: automatisch
  • Jedes IPv6-Interface hat immer eine. Wird für Nachbar-Erkennung (NDP) und Router-Austausch genutzt.

Unique Local

fc00::/7
  • Bereich: fc00::/7
  • Praxis: fd00::/8
  • Routbar: Nein (im Internet)
  • Das IPv6-Pendant zu RFC-1918. Frei wählbar, nur innerhalb der eigenen Organisation gültig.

Multicast

ff00::/8
  • Bereich: ff00::/8
  • Zweck: Gruppenansprache
  • Ersetzt: Broadcast
  • z.B. ff02::1 = alle Knoten, ff02::2 = alle Router.

Loopback

::1/128
  • Adresse: ::1
  • Entspricht: 127.0.0.1
  • "Localhost" – verweist immer auf das eigene Gerät. Nur eine einzige Adresse, kein ganzes /8.

Unspecified

::/128
  • Adresse: ::
  • Zweck: "noch keine Adresse"
  • Wird z.B. beim DHCPv6-Start genutzt, solange das Gerät noch keine eigene Adresse hat.

IPv4-mapped

::ffff:0:0/96
  • Beispiel: ::ffff:192.168.1.1
  • Zweck: Dual-Stack-Sockets
  • Erlaubt es, IPv4-Adressen in IPv6-Notation darzustellen – für Übergangszeiträume.

Anycast

kein eigenes Präfix
  • Bereich: aus Global Unicast
  • Prinzip: 1 Adresse, n Geräte
  • Pakete gehen an das nächstgelegene Gerät der Gruppe. So funktionieren z.B. die Root-DNS-Server.

Subnet-Router Anycast

::/64
  • Adresse: alle Host-Bits = 0
  • Beispiel: 2001:db8::
  • Das ist die IPv6-"Netzwerkadresse". Sie ist reserviert, aber nicht wie ein IPv4-Netzwerk gesperrt.

IPv4 vs. IPv6 – was sich ändert

Private Bereiche (RFC 4193)

Das IPv6-Pendant zu den privaten IPv4-Adressen sind die Unique Local Addresses (ULA). Sie werden im Internet nicht geroutet und können in jedem Netz frei verwendet werden – z.B. für interne Dienste, die auch ohne Internetverbindung erreichbar sein sollen.

Typ Bereich Hinweis
Unique Local fc00::/7 In der Praxis immer mit fd00::/8 gebaut
Link-Local fe80::/10 Automatisch auf jedem Interface, nie geroutet
Loopback ::1/128 "Localhost" – nur eine einzige Adresse

Praxis-Tipp: Ein Heimrouter bekommt vom Provider oft ein /56. Das reicht für 256 /64-Subnetze – genug für VLANs, Gäste-WLAN, IoT und mehr.
