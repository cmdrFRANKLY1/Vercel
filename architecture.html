Site architecture

A field guide to how the dashboard and its topics fit together, and where to add or remove things.

Overview

The app is a static HTML site. There is no build step, no bundler, no framework. index.html loads a handful of classic scripts from resources/modules/. One of those scripts (topics.js) reads topicList.json and loads each topic. Each topic calls registerTopic(…), which drops it into App.topics._registry. The dashboard reads that registry and renders a card per topic.

One rule: if a topic is not in App.topics._registry, it will not appear on the dashboard. Registration is the only way in.

Mental model

Everything you see fits into three layers:

Layer Responsibility Examples
Shell Sidebar, dashboard, calendar, modals, i18n, theming. index.html, resources/modules/*.js
Topic entry point Registers one topic with the shell. A thin file. wiso/topic_wiso.js, dataprotection/topic_dataprotection.js
Topic data & behaviour The actual content and interactions for that topic. wiso/data/, wiso/controllers/

The shell does not know what a "WiSo" is. It only knows the shape a topic object must have: id, titleDe, sections, illustrations, and so on. Everything else is up to the topic.

How a topic loads

  1. index.html loads resources/modules/topics.js as a classic script.
  2. That script defines registerTopic() and exposes it on window.
  3. On DOM ready, topics.js fetches topicList.json and iterates the paths.
  4. For each path, it calls import(path) — a dynamic ES module import. This works for classic scripts too, so mixed topics are fine.
  5. The topic entry point executes. It imports its data, calls registerTopic({...}).
  6. registerTopic drops the topic into App.topics._registry.
  7. When you click a dashboard card, the shell renders the topic object as HTML.
MIME trap: if a module's URL 404s, Live Server serves its HTML 404 page. The browser refuses to execute an HTML page as a module and shows "disallowed MIME type (text/html)". That message always means file missing or wrong path, never an actual MIME problem.

How to add things

Add a sub-topic to an existing section

Say you want to add "4.3 Beitragsbemessungsgrenze" under Sozialversicherungen.

  1. Open wiso/data/sections/04-social-security.js.
  2. Find the subtopics: [...] array.
  3. Append a new object at the end of the array:
{
    id: 'beitragsbemessungsgrenze',
    titleDe: '4.3 Beitragsbemessungsgrenze',
    titleEn: '4.3 Contribution Ceiling',
    htmlDe: `<p>Die Beitragsbemessungsgrenze ist …</p>`,
    htmlEn: `<p>The contribution ceiling is …</p>`
}
  1. Save the file.
  2. Hard-reload the page (Ctrl+Shift+R).

The new card appears in section 4, and the sidebar TOC picks it up automatically. No other file needs to change.

Add a whole new section

  1. Create wiso/data/sections/10-labor-market.js:
// resources/topics/wiso/data/sections/10-labor-market.js

export const section = {
    id: 'arbeitsmarkt',
    titleDe: '10. Arbeitsmarkt und Tarifrecht',
    titleEn: '10. Labor Market and Collective Bargaining',
    introDe: 'Grundlagen zu Tarifverträgen und Arbeitsmarkt.',
    introEn: 'Fundamentals of collective agreements.',
    subtopics: [
        {
            id: 'tarifvertrag',
            titleDe: '10.1 Der Tarifvertrag',
            titleEn: '10.1 Collective Agreement',
            htmlDe: `<p>…</p>`,
            htmlEn: `<p>…</p>`
        }
    ]
};
  1. Register it in wiso/data/sections.js:
import { section as s10 } from './sections/10-labor-market.js';

export const sections = [s1, s2, s3, s4, s5, s6, s7, s8, s9, s10];
  1. Reload. Section 10 appears at the end of the WiSo page.
Numbered files matter. The 01-, 02-, … prefixes are purely cosmetic — they do not control order. Order comes from the sections array in data/sections.js. Renumbering a file without updating its import breaks nothing as long as the path matches.

Add an illustration

  1. Create wiso/data/illustrations/tax-shift.js:
export const taxShift = {
    id: 'wiso-vis-tax-shift',
    titleDe: 'Steuerinzidenz',
    titleEn: 'Tax Incidence',
    descDe: 'Wie sich eine Steuer verteilt.',
    descEn: 'How a tax distributes.',
    html: `<div class="my-illustration">…</div>`
};
  1. Register in wiso/data/illustrations.js:
import { taxShift } from './illustrations/tax-shift.js';

export const animations = [matrix, supplyDemand, marketPower, taxShift];
Interactive illustration? Put the JS in wiso/controllers/your-illustration.js and import it from topic_wiso.js. The illustration's html field then just contains the canvas or a placeholder element the controller attaches to.

Add a quiz question

  1. Open wiso/data/quiz-data.js.
  2. Add an entry to QA (answer key + explanation):
export const QA = {
    // …
    hrTarifvertrag: ['a', 'Richtig. Der Tarifvertrag wird zwischen Gewerkschaft und Arbeitgeberverband geschlossen.']
};
  1. Add the question itself to QUIZ_QUESTIONS (only if it belongs to the final quiz):
export const QUIZ_QUESTIONS = [
    // …
    ['Wer schließt einen Tarifvertrag?',
     ['Gewerkschaft und Arbeitgeberverband', 'Einzelner Arbeitnehmer und Chef', 'Der Betriebsrat'],
     0]
];
  1. To render the question in a section, drop this markup wherever you want it:
<div class="wiso-task" data-wiso-question="hrTarifvertrag">
    <div class="font-semibold text-sm mb-2">Wer schließt einen Tarifvertrag?</div>
    <div class="wiso-choices grid gap-2">
        <button class="wiso-choice" data-wiso-value="a">Gewerkschaft und Arbeitgeberverband</button>
        <button class="wiso-choice" data-wiso-value="b">Einzelner Arbeitnehmer und Chef</button>
        <button class="wiso-choice" data-wiso-value="c">Der Betriebsrat</button>
    </div>
    <div class="wiso-feedback hidden mt-3 p-3 rounded text-sm"></div>
</div>
The handelsrecht.js controller auto-discovers any [data-wiso-question] element, so no code change is needed.

Add a quick link or footer link

Open wiso/meta.js.

Quick link (hero panel, top of page):

quickLinks: [
    // …
    { icon: 'fa-people-arrows', href: '#arbeitsmarkt', switchToDoc: true, labelDe: 'Arbeitsmarkt', labelEn: 'Labor Market' }
]

Footer link (external resource, bottom of page):

links: {
    items: [
        // …
        { icon: 'fa-book', href: 'https://www.bmas.de/', target: '_blank', labelDe: 'BMAS', labelEn: 'Federal Ministry of Labour' }
    ]
}

Add an interactive controller

  1. Create wiso/controllers/your-widget.js:
(function () {
    'use strict';

    function init() {
        document.querySelectorAll('[data-my-widget]').forEach(function (el) {
            if (el.__myWidget) return;
            el.__myWidget = true;
            // wire up behaviour
        });
    }

    function start() {
        init();
        setInterval(init, 500);  // re-scan on re-renders
    }

    if (document.readyState === 'loading') {
        document.addEventListener('DOMContentLoaded', start);
    } else {
        start();
    }
})();
  1. Import it from wiso/topic_wiso.js:
import './controllers/matrix-hover.js';
import './controllers/handelsrecht.js';
import './controllers/your-widget.js';

Add a whole new topic

  1. Create resources/topics/your-topic/ with the same skeleton used by WiSo: meta.js, topic_your-topic.js, data/, controllers/.
  2. In topic_your-topic.js, import from ./meta.js and call registerTopic({...}).
  3. Add the path to topicList.json:
{
    "topics": [
        // …
        "resources/topics/your-topic/topic_your-topic.js"
    ]
}
Nesting: set parentId in your topic's meta.js to nest it inside another topic's card on the dashboard. E.g. parentId: 'wiso' would make your topic appear as a sub-topic of WiSo.

How to remove things

Remove a sub-topic or section

  1. Open the section file, e.g. wiso/data/sections/04-social-security.js.
  2. Delete the object from the subtopics array, or delete the whole file for a section removal.
  3. If you deleted the file, also delete its import and array entry in wiso/data/sections.js.
  4. Reload. The card is gone.
Watch for orphan references. If a quickLink in meta.js points to #arbeitsmarkt and you removed section arbeitsmarkt, the link will silently do nothing when clicked. Grep meta.js for the removed ID before you save.

Remove a whole topic

  1. Open topicList.json.
  2. Delete the topic's path line.
  3. Optionally delete the topic's folder under resources/topics/. Nothing in the shell references it after step 2.
  4. Reload. The dashboard card is gone.

Golden rules

# Rule Why
1 One file per section, one file per illustration. Diffs stay small; entry points never need to change.
2 IDs are global within a topic. They become DOM anchors and TOC hrefs. Collisions break scrolling.
3 Every user-visible string has a De and an En. The i18n layer toggles both; a missing field renders blank.
4 Never edit topic_wiso.js to add content. Only controller imports belong there. Content goes in data/.
5 HTML strings are plain strings, not templates. No ${} inside htmlDe. Generate dynamically only via controllers.
6 Always hard-reload after editing data. Sections are read once at page load. No hot-reload.
7 Keep assemblers in sync. New file under data/sections/ ⇒ new import in data/sections.js.

Common pitfalls

"Disallowed MIME type (text/html)" in the console

Always a missing or misnamed file. The browser requested a .js URL, the server returned its HTML 404 page, and the module loader refused to execute it.

Fix: look at the URL in the error, walk the same path in VS Code, compare the last segment. Rename or move the file to match.

Topic loads but the dashboard card never appears

Two causes: (a) registerTopic was never called because a transitive import failed silently, or (b) init.js rendered the dashboard before loadAllTopics() resolved. Open the console and check Object.keys(App.topics._registry) — if your topic ID is missing, it's (a).

Sections appear but no sub-topic cards

The html / htmlDe / htmlEn field is empty, or it still contains the placeholder <!-- paste … --> comment. The wrapper renders, the body is empty. Replace the comment with real markup.

i18n toggle breaks

Every language-aware element must have both data-lang-de and data-lang-en. If only one is present, the element stays visible in both modes, or disappears entirely.

localStorage from a previous version wins

WiSo's quiz stores answers under wiso-handelsrecht-v1. Bump the version string in wiso/controllers/handelsrecht.js if the storage shape changes; otherwise stale data can appear on reload.
